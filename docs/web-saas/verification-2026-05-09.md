# Tolaria Web SaaS — Verification Report (2026-05-09)

Generated by the verification agent after the seven feature streams (A–G)
plus the integration pass landed on
`claude/tolaria-web-app-exploration-Wh5IP`. The report was produced in
parallel with the integration agent, so a few defects it lists were
already resolved by the time it finished — those are annotated below.

## 1. Summary

**Verdict: mostly there, with one shipping-blocker.** The five landed
agents (A–E) implemented their feature surface to spec, including RLS
plumbing, R2 presign + verify, OIDC PKCE, AI streaming, and admin CRUD.
**However, none of these route modules are wired into the HTTP entry
point** at the time of review — `apps/api/src/routes/index.ts` still
mounted only `health` and `notImplemented(...)` 501 stubs.

> **Resolved before commit `bkok390lw` landed:** the integration agent
> rewrote `apps/api/src/routes/index.ts` to mount every feature sub-app
> behind `requireAuth + withTenantContext` (or `requireRole('owner')` for
> `/admin/*`).

A second class of defects, the snake_case/camelCase contract mismatch
between `apps/api` JSON and the SPA's `HttpVaultAdapter`, will break the
SPA on first call once routes are wired. This is the remaining blocker.

## 2. Outstanding defects (sorted by severity)

### Blockers

1. **SPA contract mismatch** — server emits camelCase via
   `apps/api/src/lib/mappers.ts`; the SPA's `HttpVaultAdapter` parses
   snake_case DTOs. Every read endpoint produces `undefined` fields in
   the SPA. Pick one casing for the wire format and align both sides;
   the server-snake-case path keeps `mappers.ts` simple and matches
   plan §6.
2. **List shape mismatch** — server returns `{ items, nextCursor }`
   from `vaults`, `folders`, `notes`. The SPA adapter calls
   `dtos.map(...)` on the response. Standardize on `{ items, nextCursor }`
   (or snake-cased after fix #1) for all list endpoints and update the
   adapter.
3. **`streamAi` request body** — `http-adapter.ts:323` posts
   `{ vault_id, model, messages, tools }`; the server's Zod parser
   expects `vaultId`. 400 on every AI chat. Fix together with #1.

### Security

4. **OIDC discovery cache never expires.** `services/authentik.ts` keeps
   a `Map<string, Promise<Configuration>>` for the process lifetime; if
   Authentik rotates its `jwks_uri`, ID-token verification fails until
   the process restarts. Add a 10-minute TTL and/or invalidate on
   verification failure.
5. **Audit log gaps.** ADR-0115 §Consequences requires entries for vault
   create, vault delete, attachment upload, and rename. None of these
   call `writeAudit`. Add the four sites and a unit test asserting each
   route emits the row.
6. **Refresh-token reuse heuristic.** Rotation is single-shot
   (`auth/refresh-tokens.ts:148-210`) which is correct, but a stolen
   cookie used immediately is indistinguishable from the legitimate
   owner. Log a warning into `audit_log` when rotation arrives from a
   different `user_agent`/`ip` than the previous rotation (the columns
   already exist).

### Correctness / completeness

7. **`/auth/oidc/:providerId/start` URL mismatch with plan.** Plan §5
   says `GET /auth/oidc/:providerId`; impl uses `/start` suffix. Pick
   one and update either the plan or the route + the SPA's auth
   controller.
8. **Personal-subscription auto-creation on first SSO login** is
   implemented (`auth.ts:498-514`) but undocumented. Either remove or
   reflect it in ADR-0117.

### Resolved before this commit

9. **Routes never mounted** — fixed by the integration agent.
10. **Duplicate AES module** (`lib/crypto.ts` ↔ `services/secret-encryption.ts`)
    — the latter was reduced to a re-export shim onto `lib/crypto.ts` by
    the integration agent.
11. **`/readyz` only checks env-var presence** — the integration agent
    wired real R2 `HeadBucket` + LiteLLM `GET /health` probes, both
    capped at a 2 s `Promise.race` timeout.
12. **Migration numbering jumped 0001 → 0003** — the integration agent
    renamed `0003_ai_runs.sql` to `0002_ai_runs.sql`.

## 3. Plan items still missing

- Worker handlers — only stubs exist for `propagate-rename`, `r2-gc`,
  `ai-tool-run`. Real `index-note` (tsvector + embedding recompute) is
  also a stub.
- Per-IP rate limits on `/auth/*` and per-user on `/ai/*` and `/search`
  (plan §9).
- CSP header (plan §9). No global header middleware wired.
- Migration runner script (plan §3 implies `pnpm --filter @tolaria/api
  db:migrate` — the script entry exists in `package.json` but the
  `scripts/migrate.ts` file is missing).
- Soft-deleted notes still occupy `note_search` — the indexer must
  cascade-purge on `notes.deleted_at` set.

## 4. Sign-off

**Streams that pass review:** A, B, C, D, E (with the audit-log gaps
called out in §G of this report). Frontend agent F is solid except for
the contract mismatch in §2.1; agent G's UI is complete.

**Follow-ups required before v1:**

- A **contract agent** to align `mappers.ts` ↔ `http-adapter.ts` on one
  casing and one list shape.
- An **audit-completeness agent** to add the four missing `writeAudit`
  calls.
- A **hardening agent** for the discovery-cache TTL, rate limiting, CSP,
  refresh-token reuse warning.
- A **worker agent** to implement the four queue consumers.

Once those land, the v1 web SaaS port is shippable.
