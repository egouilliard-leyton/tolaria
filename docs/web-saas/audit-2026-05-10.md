# Tolaria Web SaaS — Wave-2 Audit (2026-05-10)

Read-only audit walking every concrete claim in
`docs/ARCHITECTURE-WEB-SAAS.md` plus ADRs 0115/0116/0117 against the
current code state on `claude/tolaria-web-app-exploration-Wh5IP`. This
audit feeds the next implementation wave and is intentionally
pessimistic.

---

## 1. Headline

The web SaaS port is **structurally complete but not shippable to
external users**. Every plan phase has landed real code (API routes
wired, worker handlers non-stub, RLS + FORCE RLS on every tenant
table, R2 presign+verify, OIDC PKCE, AI streaming, SSO admin UI,
Sync-to-Cloud dialog, web build target). Five of the six top
defects from `verification-final.md` are resolved (auth-fragment
parsing, sso-list contract, admin envelope alignment for sso,
`r2-gc` schedule wired, OIDC discovery TTL).

The remaining surface is concentrated in four areas:

1. **Wire contracts the SPA still gets wrong** — the standalone
   `admin-api.ts` client reads `body.code/body.message` flat (server
   emits `{ error: { code, message } }`), `inviteUser` expects
   `{ inviteUrl, member }` but server returns `{ user,
   acceptInviteUrl, expiresInSeconds }`, and the `SsoProvider` shape
   uses `jit` + `hasSecret` while the server returns
   `jitProvisioning` + `clientSecretSet`.
2. **Desktop "synced mode" is half-built** — `cloudSync` config is
   only in `localStorage`, the desktop boot never reads it to swap
   adapters, the HTTP adapter has no `createVault`, `TauriVaultAdapter`
   throws on 8 of its 12 methods, and the Settings panel still renders
   AutoGit and CLI-agent sections in the web build.
3. **Operational hygiene** — `apps/api` ships a `scripts/migrate.ts`
   reference that does not exist; no platform-default Authentik seed
   exists anywhere; no `dev-bootstrap.sh`; no `pnpm test:integration`;
   no CORS middleware (cross-origin web → api requires it); no
   healthchecks on `api`/`worker` compose services; no CSRF / Origin
   check on `/auth/refresh`.
4. **Plan items that are silently NULL** — `note_search.embedding`
   is permanently NULL (no model, no env, no cost cap, no backfill);
   `WEB_SAAS_ENABLED` flag is defined but never read; rate-limit
   defaults aren't documented for ops; `audit_log` has no retention
   policy; account linking is undocumented in ADR-0117 (the code
   silently links cross-provider on email match).

Below: 75 gaps, ten proposed parallel fix bundles, an honest list of
what is already done, and a concrete dispatch plan.

## 4. What is genuinely done

So the next dispatch does NOT redo any of this:

- **RLS topology** is correct: every tenant-owned table has `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` and a policy keyed on `app_subscription_id()`. `withTenant` is the single chokepoint; the worker mirrors it. `withPlatformContext` is the only sanctioned escape hatch and is used by exactly three call sites (auth-path).
- **Route mounting** in `apps/api/src/routes/index.ts` is real (verification-final §1 fixed it). `requireAuth + withTenantContext` wraps the authed surface; `/admin/*` is gated by `requireRole('owner')` (sso) or `requireRole('owner','admin')` (users).
- **OIDC PKCE** start/callback/refresh/logout work end-to-end. Discovery has a 10-min TTL with stale-on-failure semantics. PKCE only — no implicit/hybrid path.
- **Vault/notes/folders/search/rename** routes all exist with snake_case wire shapes the SPA's `HttpVaultAdapter` actually reads. Bare-array `GET /vaults` and `GET /folders`; `{ items, next_cursor }` for notes. Optimistic concurrency via `version`.
- **R2 presign+verify** lifecycle correct: PUT presign with signed `x-amz-meta-sha256`, HeadObject verify on size+sha, 302 redirect on GET, soft-delete + `r2-gc` job on DELETE.
- **`/ai/chat` SSE** with credit decrement + per-subscription model registry; client-side tool execution via `/ai/chat/tool-result` round-trip.
- **`/ai/agent/run` SSE** with server-side vault tools running inside `withTenant` and a 20-step safety ceiling.
- **Worker handlers** for `index-note`, `rebuild-vault-index`, `propagate-rename`, `ai-tool-run` (with `summarize-vault` and `rebuild-graph`), `r2-gc` (both per-id and `unverified-sweep` modes) all exist. The `unverified-sweep` is now scheduled every 10 minutes from `apps/worker/src/index.ts:71-76`.
- **Worker tests in CI**: `.github/workflows/saas-ci.yml:33` runs `pnpm --filter @tolaria/worker test` after the api tests. The defect from `verification-final.md` §2.5a is resolved.
- **Auth fragment fix**: `src/lib/auth/web-auth.ts:60-64` now reads from `window.location.hash` first, falling back to query string. The verification-final §3.1 blocker is resolved.
- **SSO admin DTOs**: `GET /admin/sso/providers` returns a bare array; POST/PATCH return bare DTOs; DELETE returns 204. The verification-final §3.2 mismatch for **SSO** routes is resolved. (Users routes still need work — see G03.)
- **`clientIp` shared helper**: `apps/api/src/lib/client-ip.ts` honors `TRUST_PROXY` and is used by both auth and rate-limit. Verification-final §3.3 is resolved.
- **`/readyz` real probes**: HeadBucket + LiteLLM `/health` with 2 s Promise.race timeout.
- **Migration `0001_init.sql` + `0002_ai_runs.sql` + `0003_rate_limits.sql` + `0004_ai_tool_runs_output.sql`** all present and applied in order by `db/migrate.ts`.
